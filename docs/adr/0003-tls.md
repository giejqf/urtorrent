# ADR 0003: TLS is rustls with its default crypto provider

- Status: accepted (2026-09-19, maintainer decision)
- Relates to: AGENTS.md 5.3, 6 (accepted differences)

## Decision

HTTPS trackers and HTTPS web seeds use **rustls** through its buffer-in /
buffer-out (`Connection::read_tls` / `write_tls`) API so that ciphertext moves
over `uring` sockets. The default crypto provider (aws-lc-rs) is used; "pure
Rust" is required for the I/O and protocol stack, not for crypto primitives
(SHA-1/SHA-256/RC4/bignum also come from audited crates that may contain
assembly). No OpenSSL, no native-tls (`cargo-deny` bans them).

## Consequences

- The TLS ClientHello differs from the oracle's OpenSSL one. This is an
  accepted difference (AGENTS.md 6) and is excluded from the discriminator.
- Cheap parity is still done: SNI is sent; ALPN is offered only if the
  oracle does (captured, not assumed); roots come from `webpki-roots` with an
  option to add a custom CA (the test CA in `testkit`).
- The test harness (`tap-tracker`) also uses rustls, with the `ring` provider
  to keep tooling builds light; that choice does not leak into the library.
