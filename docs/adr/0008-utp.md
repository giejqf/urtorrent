# ADR 0008: uTP (BEP 29) as a sans-IO transport on the UDP listen socket

Date: 2026-09-20. Status: accepted.

## Context

uTP was the second post-0.1.0 item (AGENTS.md 8) and the one the `Transport`
enum (ADR 0006) was left open for. The oracle speaks it by default and, as
the capture showed, dials *every* new peer over uTP first, so a client
without it is visibly different to any peer that watches how it connects.
The design had to keep the sans-IO discipline (5.2), move every datagram
through the ring's UDP sockets (rule 4), reproduce libtorrent's wire shape
(6; now `docs/quirks.md` Q21) and leave the peer state machine untouched.

## Decision

1. **`crates/utp` is a pure state machine**: `utp::Socket` takes datagrams
   (`incoming`), time (`tick`), application bytes (`write`) and close
   requests, and yields datagrams (`poll_outgoing`), received chunks
   (`read`) and notifications (`take_notify`). `utp::Manager` is the
   per-port connection table: id allocation (outgoing `send_id` random,
   `recv_id = send_id - 1`; incoming `send_id = SYN id`, `recv_id = id + 1`),
   demultiplexing on `(recv_id, remote)`, SYN acceptance (a flood guard at
   twice the connection limit), the deferred ack that libtorrent sends once
   per receive round, and the MTU restriction learnt from connections that
   died on oversized packets.
2. **libtorrent's `utp_stream` ported with attribution** (NOTICE): LEDBAT
   with slow start (target delay 100 ms, gain 3000, ssthres on the first
   over-target sample), the delay-base history (20 one-minute slots, clock
   drift compensation), the RTT estimator (mean + 2 × deviation, 500 ms
   floor, doubling per timeout, 60 s cap), loss handling (halve once per
   RTT and at most every 100 ms; 3 duplicate acks or a selective ack
   covering 3 later packets trigger a fast resend), retransmission limits
   (3 data, 2 SYN, 2 FIN; an unconfirmed peer fails at the first timeout, so
   a SYN is never resent), nagle (one undersized packet in flight), the
   selective-ack extension sized `ceil(reorder span / 8)`, the close-reason
   extension, the 1 MiB receive buffer as the advertised window, and
   path-MTU discovery: probes use the floor/ceiling mid-point, everything
   else the floor, so a v4 connection climbs 528 → 990 → 1221 → 1336 → 1394
   → 1423 → 1437 → 1444 → 1448 → 1450 → 1451 payload bytes (1471-byte
   datagrams) exactly as the oracle does. Header timestamps are
   `CLOCK_MONOTONIC` microseconds like libtorrent's. Not ported because
   it cannot exist with completion-based I/O: the `EWOULDBLOCK` stall
   machinery (sends never block us).
3. **The engine owns I/O.** `session::engine::utp::UtpHost` wraps the
   manager: the UDP demultiplexer hands it every datagram whose first byte
   has version nibble 1 (KRPC is checked first: `'d'` is 0x64, never
   version 1; a tracker reply's first byte is 0), tells it when a receive
   round is over (deferred acks go out then, wakers fire), and the session
   ticker (100 ms) drives timeouts. A SYN that opens a connection becomes an
   incoming peer through the same `run_incoming` path as an accepted TCP
   socket; `Transport::Utp(UtpStream)` implements `recv` / chunks /
   `send_all*` so `peer.rs` did not change beyond the chunk type
   (`Chunk::{Ring, Owned}`).
4. **UDP I/O got its own fast path**: one multishot `recvmsg`
   (`uring::UdpSocket::recv_multi`, kernel 6.0+) per UDP socket into a
   provided buffer ring (256 × 2 KiB), draining up to 64 datagrams per
   wakeup; and one ordered send queue per socket that submits 32 datagrams
   at a time and waits for the batch before the next. The queue matters: a
   window's worth of packets pushed into the socket as one burst arrived
   out of order and overflowed the receiver, which the oracle then reported
   as selective acks and losses; paced batches behave like libtorrent's
   synchronous sends. Path-MTU probes go out alone with `IP_MTU_DISCOVER =
   IP_PMTUDISC_DO` set around the send (v4 only, as libtorrent does);
   `EMSGSIZE` is reported back to the connection as a rejected probe.
5. **Transport choice is a policy, TCP first by default**
   (`SessionBuilder::transports(TransportPolicy)`; maintainer decision,
   2026-09-20: TCP performs better, so libtorrent's uTP-first default is
   *not* copied — an L3 nuance, recorded in `docs/quirks.md` Q21).
   `PreferTcp` (default) dials TCP and accepts both; an address whose TCP
   dial fails — refused, timed out, or closed before any handshake byte,
   which is how a uTP-only libtorrent peer treats TCP — gets one uTP attempt
   right away and stays on uTP while that works. `PreferUtp` is libtorrent's
   order: every peer is assumed to speak uTP (`torrent_peer::supports_utp`
   starts true), a failed uTP dial falls back to TCP at once
   (`fast_reconnect`) and is remembered unless a PEX message flags the
   address uTP-capable; peers reached over uTP are confirmed. `UtpOnly`
   (qBittorrent's "μTP only") dials only uTP and drops accepted TCP
   connections; `TcpOnly` ignores SYNs (no RESET, like libtorrent) and never
   dials uTP. Our PEX `added` flags carry `0x04` for peers connected over
   uTP, as the oracle's do.
6. **Close reasons**: our disconnect reasons map to libtorrent's
   `close_reason_t` codes (`duplicate peer id` 1, `torrent stopped` 2,
   `banned` 5, `both seeds` 6, `inactive` 10, protocol errors 263) and ride
   in the FIN's extension 3, and in the ack of the peer's FIN when set.
   Payload that arrives in the same receive round as the FIN while the
   reader is idle is discarded, because that is what libtorrent's peer
   connection does with data delivered together with end-of-stream
   (`docs/quirks.md` Q21).
7. **Testing.** `capture_utp` (goldens: `utp-shape.json` per family, the
   pcap stays in the run directory), `utp_leech_from_oracle` (v4/v6),
   `utp_seed_to_oracle`, `utp_shape` (differential: SYN, SYN-ACK and
   first-data shapes, initial window, MTU ladder, largest datagram, FIN
   shape and FIN-ack extensions, as connector and as acceptor);
   `oracle_utp_tcp_fallback` runs us TCP-only so the oracle's uTP dial fails
   and its TCP fallback is exercised. In-process:
   `crates/session/tests/utp.rs` (uTP-only leecher, MSE over uTP, the default
   TCP-first policy, `PreferUtp`, fallbacks in both directions, disabled
   uTP) and
   `crates/utp/tests/sim.rs` (a simulated network with latency, loss and
   reordering: integrity both ways, the MTU ladder, the close handshakes,
   the FIN-round drop). Fuzz: `utp_packet`. `xtask syscalls` transfers
   over both TCP and uTP.

## Consequences

- Default connections stay on TCP; uTP carries peers that TCP cannot reach
  and whatever dials us over UDP (libtorrent peers try uTP first, so many
  incoming connections are uTP). Throughput over loopback is lower than
  TCP's (one datagram per packet, no zero-copy) — `docs/perf.md` has the
  numbers; the TCP path is unchanged.
- The UDP demultiplexer's multishot receive also serves the DHT and UDP
  trackers.
- `ut_holepunch` (BEP 55) is now possible; it is the next item. Teredo
  destinations get a 1280-byte link MTU like libtorrent's; no other MTU
  source is consulted (libtorrent does the same in 2.0).
