# ADR 0007: DHT (BEP 5) as a sans-IO node per address family

Date: 2026-09-20. Status: accepted.

## Context

0.1.0 and 0.2.0 were TCP-only and tracker / PEX / LSD-driven; the DHT was the
first post-0.1.0 item (AGENTS.md 8). The design had to keep the sans-IO
discipline (5.2), run its datagrams on the ring's UDP sockets through the
demultiplexer reserved for it (4, 5.3), match the oracle's wire shape (6,
now `docs/quirks.md` Q20) and keep private torrents silent (rule 2).

## Decision

1. **`crates/dht` is a pure state machine.** `dht::Node` takes datagrams
   (`incoming`), time (`tick`) and requests (`bootstrap`, `announce`,
   `get_peers`, `add_node`) and emits `Action`s (`Send`, `Peers`,
   `LookupDone`, `ExternalIp`, `Bootstrapped`). Randomness comes through
   `profile::Rng`. One node per address family, as libtorrent runs one per
   listen socket; the engine passes the other family's routing table so
   `want` can be answered.
2. **libtorrent's algorithms, ported with attribution** (NOTICE): the
   routing table (extended bucket sizes 128/64/32/16/8, replacement cache,
   unpinged-until-answered, one node per IP and per /24 or /64), the
   traversal (branch factor 5 with short/hard timeouts of 1 s / 15 s, 100
   results, per-prefix filtering, announce to the 8 closest token holders),
   bootstrap and refresh, the token scheme (4-byte SHA-1 prefix over address
   text + secret + info-hash, rotated every 5 min), the peer store (2000
   torrents, 500 peers, 100 per reply, 30-min expiry, BEP 33 filters, BEP 51
   samples), the DoS blocker and BEP 42 id generation. Simplifications that
   are invisible on the wire: no prefix-diversity classification when
   replacing bucket nodes, no obfuscated lookups, no BEP 44 item storage.
3. **The engine owns I/O and policy.** `session::engine::dht::Dht` feeds the
   nodes from the UDP demultiplexer (a datagram starting with `d` is KRPC;
   tracker replies never do), ticks them once a second from the session
   ticker, sends through the same sockets, forwards found peers as
   `PeerSource::Dht`, casts `ip` replies as external-address votes
   (`Source::Dht`) and gives the node a BEP 42 id once an address is voted
   in, and announces torrents round-robin every `15 min / torrents` (new and
   just-finished torrents within 4 s), never private ones. Peers' `port`
   messages become `add_node` probes; we send `port` after the have-state to
   DHT-capable peers while a node runs (`wire::ConnectionParams::dht_port`).
4. **State**: `Session::dht_state()` returns a small bencoded dictionary
   (`id4`, `id6`, `nodes`, `nodes6`, `v: 1`) that `SessionBuilder::dht_state`
   restores so a node comes up warm; routers come from the profile
   (`DhtShape::bootstrap_nodes`, qBittorrent's list) unless the caller sets
   `dht_bootstrap_nodes` (an empty list means none — tests must, rule 3).
5. **Testing.** The lab got one /24 (v4) and /64 (v6) per actor (ADR 0002
   amended): libtorrent keeps one node per /24 per bucket and per lookup, so
   a single-/24 lab could never show a second hop. `tap-dht` is a scriptable,
   recording DHT node (router mode learns queriers and serves stored
   announces). Scenarios: `capture_dht` (goldens), `dht_leech_from_oracle`
   (v4/v6), `dht_seed_to_oracle`, `dht_shape` (differential: bootstrap /
   lookup / announce shapes, replies to 17 probes, `port` position), and
   `private_no_pex_lsd` now also proves no KRPC about a private torrent while
   the node is running. In-process: `crates/session/tests/dht.rs` (three
   engines in distinct loopback /24s) and `crates/dht/tests/sim.rs` (a
   simulated network). Fuzz: `dht_krpc` (parser plus the node's whole
   incoming path).

## Consequences

- The `native` profile's handshake now carries the DHT bit whenever a node
  runs; the qbt profile always did (Q1).
- `recv_multi`-style multishot `recvmsg` for the UDP sockets is still a
  single-shot loop; it is on the list with uTP, which will share the
  demultiplexer.
- BEP 44 (`put`/`get` items) is a documented gap (Q20); BEP 43 read-only
  mode is supported (`SessionBuilder::dht_read_only`).
